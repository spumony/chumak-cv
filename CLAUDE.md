# CV-сайт — дизайн-конституция

Этот файл — источник истины по дизайну и правилам проекта. Перечитывай его в начале каждой сессии. Если что-то противоречит этому файлу — спрашивай у пользователя, не предполагай.

## Стек (не меняй без согласования)

- Vite + React 19 + TypeScript strict
- Tailwind CSS v4 (через `@tailwindcss/vite`, не v3 API!)
- Framer Motion (`motion` package)
- i18next + react-i18next
- lucide-react для иконок

## Дизайн-токены

Все цвета — через CSS-переменные в `src/index.css`. **Никогда** не хардкодь hex в JSX/TSX компонентах.

```
--bg: #0a0a0a
--bg-elevated: #141414
--border: #262626
--text-primary: #f5f5f5
--text-secondary: #a3a3a3
--text-muted: #737373
--accent: #8b5cf6
--accent-hover: #a78bfa
```

Токены заданы через Tailwind v4 `@theme` в `src/index.css` (как `--color-bg`,
`--color-accent` и т.д.). Используй **сгенерированные утилиты**: `bg-bg`,
`bg-bg-elevated`, `border-border`, `text-text-primary`, `text-text-secondary`,
`text-text-muted`, `text-accent`, `text-accent-hover`, `font-mono`. CSS-переменные
тоже доступны как `var(--color-bg)`, если нужен сырой доступ.

## Типографика

- **Inter** — основной шрифт (self-hosted через `@fontsource/inter`). Выбран вместо
  Geist Sans, потому что пакет Geist Sans содержит только латиницу и ломает
  кириллицу на двуязычном сайте. Inter покрывает латиницу + кириллицу.
- **Geist Mono** — для технологий, кода, бэйджей (содержит кириллицу).
- Минимальный размер на мобилке: 16px (иначе iOS зумит)
- Hero: `text-4xl sm:text-5xl md:text-7xl`
- Заголовки секций: `text-2xl sm:text-3xl md:text-4xl`
- Основной текст: `text-base sm:text-lg`, line-height 1.6+

## Mobile-first (НЕ переговаривается)

- Базовые стили — для мобилки, потом `sm:`/`md:`/`lg:`
- Все кликабельные элементы ≥ 44×44px (Apple HIG)
- Hover-эффекты только через `@media (hover: hover)` или `hover:` в Tailwind с осознанием, что на тач-устройствах они не сработают
- `prefers-reduced-motion` — уважай, отключай анимации
- Никогда не используй фиксированные значения в px для ширины — только `%`, `rem`, `max-w-*`
- Safe areas: `env(safe-area-inset-top)` для шапки, `env(safe-area-inset-bottom)` для футера

## Workflow для UI

### Перед изменением UI

1. Если правишь существующий компонент — открой текущее состояние через chrome-devtools MCP, сделай скриншот
2. Если работаешь со свежим синтаксисом (Tailwind v4, React 19, Framer Motion) — дёргай context7 ДО написания кода

### После любого изменения UI (обязательный чек-лист)

1. Запусти `pnpm dev` (или `npm run dev`)
2. Через chrome-devtools MCP открой `http://localhost:5173`
3. Сделай скриншоты на ширинах: **320px, 375px, 768px, 1024px**
4. Покажи скриншоты пользователю
5. Если что-то ломается на 320px — фикси немедленно перед переходом дальше
6. Прочитай console через chrome-devtools MCP — не должно быть warnings/errors

### Без визуальной проверки секцию не считай завершённой

Если по какой-то причине chrome-devtools MCP не работает — скажи об этом пользователю и спроси, как поступить. Не делай UI вслепую.

## Правила кода

- TypeScript strict, никогда `any` — если не знаешь тип, спроси
- Никаких inline-стилей кроме CSS-переменных
- Компоненты — функциональные, props типизированы явно
- Никаких лишних библиотек — только из стека выше
- Никаких бэкендов, БД, форм с отправкой — статический сайт

## Контент

Все плейсхолдеры с префиксом `TODO:` — это места, куда пользователь будет вставлять реальные данные. Не «улучшай» их, не придумывай содержимое. Структура данных: `{ ru: string, en: string }`.

## Чего НЕ делать

- Не используй Tailwind v3 API (`@tailwind base` директивы и т.д.) — у нас v4
- Не добавляй фреймворки/библиотеки без явного запроса
- Не создавай блог, формы контакта с отправкой, чат, AI-функции
- Не trust свою память по новым библиотекам — context7 знает лучше
- Не пиши «адаптивно» без проверки на 320px — всегда тестируй
